# Contributing to Olist Customer Intelligence: RFM & Retention Analytics

Thank you for your interest in contributing to this project. Contributions are welcome and appreciated.

## 📌 Scope of Contributions

You can contribute by:
- Improving documentation and project clarity
- Suggesting or refining analytics methodology
- Proposing enhancements to dashboard storytelling and business insights
- Improving code quality, readability, and reproducibility

## 🧭 Before You Start

1. Review the current `README.md` to understand project goals.
2. Open an issue (if needed) to discuss major changes before submitting a PR.
3. Keep contributions focused and well-scoped.

## 🔄 Contribution Workflow

1. **Fork** the repository
2. **Create a branch** from `main`
   - Example: `feature/improve-rfm-docs`
3. **Make your changes**
4. **Commit with clear messages**
   - Example: `docs: clarify cohort retention assumptions`
5. **Push** your branch to your fork
6. **Open a Pull Request** against `main`

## ✅ Pull Request Guidelines

Please ensure your PR:
- Has a clear title and concise description
- Explains **what changed** and **why**
- References related issues when applicable
- Avoids unrelated or oversized changes

For analytics changes, include:
- Business rationale
- Assumptions and metric definitions
- Any expected impact on dashboard interpretation

## 🧪 Data, Files, and Secrets

- Do **not** commit secrets, credentials, or tokens
- Do **not** commit large raw datasets unless explicitly required
- Follow `.gitignore` conventions for temporary and local files

## 📝 Style & Quality Expectations

- Keep documentation concise and professional
- Use descriptive naming for scripts, measures, and folders
- Prefer reproducible and transparent analytical logic

## 🤝 Code of Collaboration

Be respectful, constructive, and helpful in reviews and discussions.

## 📬 Questions

If you are unsure about a contribution idea, open an issue first so we can align quickly.

Thanks again for helping improve this project.
